# BmsSupervisor Requirements

## 1. Purpose and safety boundary

`BmsSupervisor` converts trusted cell-voltage summary data and measurement
quality into an observable BMS state, diagnostic flags, and shadow
charge/discharge recommendations.

The model answers:

```text
Is the measurement usable?
Is any cell approaching an under/overvoltage limit?
Is any cell beyond the demonstration fault limit?
What state and shadow permissions should CAN report?
```

The model does not read hardware, drive MOSFETs, balance cells, estimate SOC,
or guarantee battery safety. All thresholds below are illustrative learning
values for simulation and CAN demonstration. They require separate battery,
cell-chemistry, system, and mentor review before any physical actuation use.

## 2. Execution contract

- Call `BmsSupervisor_initialize()` once before the first step.
- Call `BmsSupervisor_step()` every 500 ms in the MVP.
- Supply `step_ms = 500` on every normal scheduled step.
- The model uses `step_ms` to accumulate entry and recovery time.
- The RTE must supply one coherent input set and must not change it during a
  step.
- One nonreentrant model instance is required.

## 3. Inputs

| Name | Type | Unit | Meaning |
|---|---|---|---|
| `min_cell_mv` | `uint16` | mV | Minimum of all 15 cells in the retained snapshot |
| `max_cell_mv` | `uint16` | mV | Maximum of all 15 cells in the same snapshot |
| `measurement_valid` | `boolean` | logical | Latest acquisition successfully published |
| `measurement_stale` | `boolean` | logical | Last successful publication exceeded its allowed age |
| `step_ms` | `uint16` | ms | Time represented by this model step; 500 in the MVP |

When validity is false or staleness is true, min/max may contain last-good
values. The model shall not use those retained voltages to claim `NORMAL`.

## 4. Outputs

| Name | Type | Meaning |
|---|---|---|
| `state` | `uint8` | Current supervisor state code |
| `warning_flags` | `uint16` | Active voltage-warning bit mask |
| `fault_flags` | `uint16` | Active voltage/measurement fault bit mask |
| `charge_allowed_shadow` | `boolean` | Observational charge recommendation |
| `discharge_allowed_shadow` | `boolean` | Observational discharge recommendation |

No output shall control hardware in the MVP.

## 5. State encoding and meaning

| Code | State | Meaning |
|---:|---|---|
| 0 | `INIT` | Initialized but no usable measurement has yet been evaluated |
| 1 | `NORMAL` | Usable measurement with no active warning or fault |
| 2 | `WARNING` | One or more delayed voltage warnings are active and no fault has priority |
| 3 | `FAULT` | One or more delayed voltage faults are active |
| 4 | `SENSOR_ERROR` | Latest measurement is invalid or stale |
| 5–255 | Reserved | Must not be generated by the model |

State priority, highest first:

```text
SENSOR_ERROR → FAULT → WARNING → NORMAL
```

`INIT` exists only until the first model step evaluates its inputs. Therefore,
the first step may transition directly from `INIT` to any other defined state.

## 6. Flag encoding

### Warning flags

| Bit | Mask | Name | Meaning |
|---:|---:|---|---|
| 0 | `0x0001` | `UV_WARNING` | Delayed undervoltage warning active |
| 1 | `0x0002` | `OV_WARNING` | Delayed overvoltage warning active |
| 2–15 | — | Reserved | Must remain zero |

### Fault flags

| Bit | Mask | Name | Meaning |
|---:|---:|---|---|
| 0 | `0x0001` | `UV_FAULT` | Delayed undervoltage fault active |
| 1 | `0x0002` | `OV_FAULT` | Delayed overvoltage fault active |
| 2 | `0x0004` | `MEASUREMENT_INVALID` | Latest acquisition invalid |
| 3 | `0x0008` | `MEASUREMENT_STALE` | Last successful acquisition stale |
| 4–15 | — | Reserved | Must remain zero |

Both measurement-quality bits may be active simultaneously. Voltage flags may
retain their internal history during `SENSOR_ERROR`, but measurement-quality
flags and state have priority and permissions remain false.

## 7. Demonstration thresholds and timing

These values are frozen only for the shadow-mode learning model.

| Condition | Enter when | Entry time | Clear when | Recovery time |
|---|---|---:|---|---:|
| UV warning | `min_cell_mv <= 3200` | 1000 ms | `min_cell_mv >= 3300` | 1000 ms |
| UV fault | `min_cell_mv <= 2800` | 500 ms | `min_cell_mv >= 3000` | 1000 ms |
| OV warning | `max_cell_mv >= 4100` | 1000 ms | `max_cell_mv <= 4000` | 1000 ms |
| OV fault | `max_cell_mv >= 4250` | 500 ms | `max_cell_mv <= 4150` | 1000 ms |

Values between an entry threshold and its clear threshold form hysteresis. An
active flag keeps its previous value in that band.

Entry/recovery timers shall:

- accumulate `step_ms` only while their condition remains continuously true;
- reset when the relevant continuous condition is broken;
- saturate instead of wrapping;
- assert or clear on the step that reaches the required duration.

When measurement quality is unusable, voltage entry/recovery timers pause and
retain their state. They resume only after a valid, non-stale measurement.

## 8. Valid versus stale behavior

- `measurement_valid = false` means the latest acquisition attempt failed.
- `measurement_stale = true` means no sufficiently recent success exists.
- Either condition causes `SENSOR_ERROR` immediately on the current step.
- Set the corresponding measurement fault bit or bits.
- Clear both shadow permissions.
- Do not use retained min/max to enter `NORMAL`, `WARNING`, or `FAULT` while
  quality is unusable.
- On the first valid and non-stale recovery step, clear measurement-quality
  fault bits and reevaluate retained/current voltage conditions. Recovery may
  go directly to `NORMAL`, `WARNING`, or `FAULT` according to active flags.

## 9. Shadow permission behavior

| Condition | Charge allowed | Discharge allowed |
|---|---:|---:|
| `INIT` | false | false |
| `NORMAL` | true | true |
| UV warning only | true | false |
| OV warning only | false | true |
| Both warnings | false | false |
| Any voltage fault | false | false |
| `SENSOR_ERROR` | false | false |

Permissions are recommendations for telemetry only. Fault behavior is
deliberately conservative because the model has no current, temperature,
contactor, or charger context.

## 10. High-level transitions

From any state on each step:

1. If invalid or stale, select `SENSOR_ERROR`.
2. Otherwise, update voltage timers and flags.
3. If a voltage fault is active, select `FAULT`.
4. Else if a voltage warning is active, select `WARNING`.
5. Otherwise select `NORMAL`.

There is no permanently latched state in the MVP. Hysteresis and recovery
timers prevent immediate chatter around thresholds.

## 11. Required deterministic scenarios

| Scenario | Required result |
|---|---|
| Startup with no valid measurement | First step enters `SENSOR_ERROR`; invalid/stale bits reflect inputs; permissions false |
| First valid normal measurement | Enters `NORMAL`; flags zero; both permissions true |
| Brief source failure | Immediately enters `SENSOR_ERROR`; retained voltages are not treated as normal |
| Stale measurement | Immediately enters `SENSOR_ERROR`; stale bit set; permissions false |
| Invalid-to-valid recovery | Clears quality bits and reevaluates voltage state on first usable step |
| UV warning entry | 3200 mV condition for two 500 ms steps asserts `UV_WARNING` and selects `WARNING` |
| UV warning interrupted | One qualifying step followed by 3201–3299 mV does not complete entry timing |
| UV warning recovery | 3300 mV or higher for two steps clears warning |
| UV fault entry | 2800 mV or lower for one 500 ms step asserts `UV_FAULT` and selects `FAULT` |
| UV fault recovery | 3000 mV or higher for two steps clears fault, then warning logic determines state |
| OV warning entry/recovery | Mirrors UV warning using 4100/4000 mV limits |
| OV fault entry/recovery | Mirrors UV fault using 4250/4150 mV limits |
| Hysteresis hold | Active flag remains active between its entry and clear thresholds |
| Simultaneous UV and OV warnings | Both warning bits active; both permissions false |
| Timer saturation | Long-duration conditions do not wrap timers or clear flags unexpectedly |

Exact-threshold, one-millivolt-inside, and one-millivolt-outside values shall be
included in the automated test vectors.

## 12. Acceptance criteria

- Every root port matches `BMS_MODEL_INTERFACE.md` in name, type, and unit.
- Every required scenario has deterministic inputs and expected outputs.
- Reserved state values and flag bits remain unused.
- Model simulation passes before code generation is permitted.
- Generated code contains no HAL, BQ, CAN, dynamic allocation, or hardware
  actuation logic.
